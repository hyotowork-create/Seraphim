## 1. 사고과정 (왜 이렇게 만들었나)

### 1-1. 두 대화에서 무엇을 골라낼 것인가
받은 자료는 성격이 다른 두 갈래였습니다.

| 자료 | 핵심 | 실행 위치 |
|---|---|---|
| ① HappyHorse 파이프라인 | 병렬 이미지 → HH 클립 → **60초 합본** | 이미지툴 + 크롬 플러그인 + ffmpeg |
| ② Remotion 설치 | React 코드로 영상 렌더 | 사용자 PC(Node/Claude Code) |

두 자료의 **공통 목표는 하나** — "세로 영상 한 편을 만든다". 그래서 ①을 **본선(main)**,
②를 **대안(alternative)** 으로 배치했습니다. ②는 실사풍 시공 영상과는 결이 달라(자막·
데이터·모션그래픽용) 본선에 섞지 않고 별도 문서로 분리했습니다.

### 1-2. "실행 가능"의 경계를 명확히
- 이 채팅 환경에서 **직접 실행 불가**: STAGE 1(이미지 생성), STAGE 2(HappyHorse 크롬
  플러그인) → 재현 가능한 **프롬프트·설정 문서**로 확정.
- 이 환경에서 **직접 실행·검증 가능**: STAGE 3(ffmpeg 합본) → **실제 코드**로 작성하고
  테스트까지 완료.

즉 "말로만 되는 부분"과 "돌아가는 코드"를 분리해, 코드는 반드시 검증하는 원칙을 세웠습니다.

### 1-3. 스크린샷 결과의 역설계
스크린샷의 "19장 이미지 → 클립 9개 → 60초"라는 숫자를 구조로 되돌렸습니다.
- 9개 건축 단계(beat) × **시작·끝 프레임 2장** = 18장, **+예비 1장 = 19장**.
- 시작·끝 프레임 쌍이 있어야 HappyHorse **First/Last frame** 모드로 "짓는 과정"의
  움직임이 만들어짐 → 단계당 클립 1개 → **클립 9개**.
- 클립 길이·개수가 흔들려도 최종은 **정확히 60초**여야 하므로, STAGE 3에서 배속
  리타이밍을 자동화하기로 결정.

### 1-4. 사용자 눈높이 (비개발자 대응)
저장소에 이미 한글 더블클릭 실행기 문화가 있었기에, 영상 합치기도
`영상_합치기.command`(Mac) / `영상_합치기.bat`(Windows) 더블클릭으로 끝나게 설계.
소재 교체가 쉽도록 이미지 프롬프트는 **공통 스타일 접미사 + 9단계 장면**으로 분리해
재사용성을 확보했습니다.

## 2. 제작과정 (실제로 무엇을 했나)

### 2-1. 환경 파악
- 저장소가 교회 주보(Eleventy) 사이트임을 확인 → 사용자가 "주보와 분리해 독립적으로"
  요청 → `video-workflow/` **독립 폴더**로 격리.
- ffmpeg 미설치 확인 → 검증을 위해 컨테이너에 설치.
```
apt-get update && apt-get install -y ffmpeg   # ffmpeg 7.1.1 설치 완료
```

### 2-2. STAGE 3 스크립트 작성
`scripts/combine_60s.sh` 의 처리 로직:
1. `clips/` 폴더에서 영상 파일을 **자연순 정렬**(clip1…clip10)로 수집
2. 모든 클립을 동일 규격(1080×1920, 30fps, SAR 1, 무음)으로 **정규화하며 이어붙임**
   (해상도·화면비가 달라도 안전하게 합쳐지도록 `scale`+`pad` 처리)
3. 이어붙인 길이 T를 `ffprobe`로 측정 → 배율 `60/T` 계산
4. `setpts=(60/T)*PTS` 로 **정확히 60초 리타이밍** + `-t 60` 으로 하드 보장
5. 결과 길이를 다시 측정해 화면에 출력

핵심 필터(개념):
```
[i]scale=1080:1920:force_original_aspect_ratio=decrease,
   pad=1080:1920:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[vi];
[v0][v1]…[vN]concat=n=N:v=1:a=0[outv]      # 이어붙이기
setpts=(60/T)*PTS                          # 60초로 배속 조정
```

### 2-3. 실제 검증 (가장 중요한 단계)
길이·해상도가 **일부러 제각각인** 테스트 클립 9개를 생성해 스크립트를 실행:
- 입력: 5, 5, 4.7, 5.3, 5, 6, 4, 5, 5초 (해상도 720×1280 / 1080×1920 / 480×854 혼합)
- 총합 45초 → 스크립트가 배율 1.333…로 리타이밍

**실행 결과 로그:**
```
🎬 클립 9개를 찾았습니다: clip01 … clip09
🧩 클립을 이어붙이는 중...
⏱  이어붙인 길이 45.000000s → 60s 로 배속 조정 (배율 1.333333333)
✅ 완성: output/final_60s.mp4
   최종 길이: 60.000초 (목표 60초)
```
**정밀 확인:**
```
duration = 60.000000
width=1080  height=1920  r_frame_rate=30/1  nb_frames=1800   (= 30fps × 60s)
```
→ 클립 길이·해상도가 흔들려도 **항상 정확히 60.000초**로 떨어짐을 실증. (테스트 산출물은
리포지토리에 커밋하지 않고 삭제)

### 2-4. 문서·실행기·커밋
- 프롬프트 문서(STAGE 1·2), 실행기(Mac/Win), 대안 문서(Remotion), 폴더 안내 작성
- 스크립트·실행기에 실행권한(`chmod +x`) 부여 후 git에 반영
- 커밋 후 지정 브랜치로 push

## 3. 결과물 (무엇이 만들어졌나)

### 3-1. 폴더 구조
```
video-workflow/
├─ README.md               ← 전체 개요·빠른 실행법
├─ 작업_보고서.md            ← (이 문서)
├─ 01_이미지_프롬프트.md      ← STAGE 1: 이미지 19장 프롬프트
├─ 02_해피호스_프롬프트.md     ← STAGE 2: HappyHorse 클립 9개 설정·프롬프트·검수
├─ ALT_Remotion.md         ← 대안: 코드(React)로 영상 만들기
├─ scripts/
│   └─ combine_60s.sh      ← STAGE 3: 정확히 60초 합본 (실행·검증 완료)
├─ 영상_합치기.command       ← STAGE 3 실행기 (Mac 더블클릭)
├─ 영상_합치기.bat           ← STAGE 3 실행기 (Windows 더블클릭)
├─ clips/                  ← 여기에 클립을 넣음 (clip01.mp4 …)
└─ output/                 ← 완성 영상이 여기에 생성됨
```

### 3-2. 3단계 요약
| 단계 | 산출물 | 규격/특징 | 상태 |
|---|---|---|---|
| STAGE 1 | 이미지 19장 프롬프트 | 9단계×시작·끝+예비1, 공통 스타일, 주제 교체 재사용 | 문서 확정 |
| STAGE 2 | HH 1.1 클립 9개 프롬프트 | 720P·9:16·5초·무음·First/Last frame·검수 규칙 | 문서 확정 |
| STAGE 3 | 60초 합본 스크립트 | 개수·길이 달라도 60.000초, 1080×1920·30fps·무음 | **실행·검증 완료** |

### 3-3. 사용 방법 (STAGE 3)
1. HappyHorse 클립을 `clips/` 에 `clip01.mp4, clip02.mp4 …` 로 저장
2. **Mac** `영상_합치기.command` / **Windows** `영상_합치기.bat` 더블클릭
   (또는 터미널 `bash scripts/combine_60s.sh`)
3. `output/final_60s.mp4` 완성

설정 변경(선택):
```bash
TARGET_SEC=30 W=1080 H=1920 FPS=30 bash scripts/combine_60s.sh
```

### 3-4. 필요 도구
- **ffmpeg / ffprobe** — Mac: `brew install ffmpeg` · Windows: `winget install Gyan.FFmpeg`
- STAGE 1·2는 각각 이미지 생성 도구 / HappyHorse 크롬 플러그인에서 진행
