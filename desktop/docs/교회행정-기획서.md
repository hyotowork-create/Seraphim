# 세라핌 「교회 행정」 기획서 (초안)

> 작성 2026-11-12 · 상태: **기획만, 구현 전** · 결정 필요 항목은 맨 아래 「정할 것」
> 계기: 청지기(cheongjigi.juchu.kr) — 개척교회용 장부·교적·기부금영수증·주일 슬라이드 웹 서비스. 기능 묶음은 참고하되 **문구·화면·코드는 가져오지 않는다.**

## 1. 한 줄 요약

세라핌에 「교회 행정」 메뉴를 더해, 소형 교회가 **헌금·지출 장부, 교인·세대, 기부금영수증**을 **교회 PC 안에서** 무료로 처리하게 한다. 서버가 없으니 교인 정보를 남에게 맡기지 않는다.

## 2. 누구를 위해

- 교인 10~50명, 재정을 목회자 부부나 집사 한 명이 엑셀·종이로 맡는 교회
- 담당자가 바뀌면 장부가 끊기고, 연말 영수증을 처음부터 다시 맞추는 교회
- 이미 세라핌으로 예배 송출·주보를 하는 교회(같은 PC, 같은 앱)

## 3. 청지기와 비교 — 어디서 다르게 이길 것인가

| | 청지기 | 세라핌 교회 행정(안) |
|---|---|---|
| 저장 위치 | 운영자 서버(AWS) | **교회 PC(로컬 SQLite)** — 위탁 계약 불필요 |
| 비용 | 1년 무료, 장부 옮기기 유료(세팅 30만 등), 이후 월 1만 원 이하 | **무료(MIT)** |
| 휴대폰·여러 명 동시 | 됨 | **안 됨**(PC 한 대). 공유는 기존 zip 백업 |
| 장부 옮겨 주는 사람 | 있음(핵심 가치) | 없음 → **엑셀 붙여넣기 가져오기**로 대신 |
| 예배 슬라이드 | 간단한 웹 슬라이드 | 이미 있음(송출·자막·성경·악보·전환효과) |
| 주보 | 없음 | 이미 있음(M7) → 생일·헌금 감사 명단 연동 가능 |

**솔직한 약점:** 청지기의 진짜 가치는 "옮겨 넣어 주는 사람"이다. 세라핌은 그 일을 붙여넣기 가져오기와 안내서로 대신하므로, 장부가 엉킨 교회에는 청지기가 더 맞을 수 있다.

## 4. 기능 범위

### 1단계 — 장부와 교인 (MVP)
- **교인 명단:** 이름·세대·직분·연락처·상태(재적·방문·이명·소천). 이름 두 글자 검색.
- **세대:** 한 집을 묶고 세대주 지정. 세대주 소천·이명 시 다른 구성원에게 넘김.
- **주간 헌금 입력:** 날짜(지난 주일 기본) → 「지난주 명단 불러오기」 → 금액만 입력. 처음 보는 이름은 교인 명단에 자동 추가 여부를 묻는다.
- **헌금 항목:** 교회가 쓰는 이름 그대로(주정·십일조·감사·선교 …), 순서 변경 가능.
- **지출:** 날짜·항목·금액·적요.
- **월별 요약:** 수입·지출·잔액, 항목별 월 표 → 인쇄(제직회 자료).
- **엑셀 붙여넣기 가져오기:** 엑셀 범위를 복사해 붙이면 열을 고르게 하는 화면(열 순서 고정 아님). 가져온 뒤 합계를 원본과 대조해 보여 준다.
- **내보내기:** 전체를 엑셀(CSV)로. 앱을 떠나도 자료는 남는다.

### 2단계 — 기부금영수증
- 연도 선택 → 발급 대상·금액을 사람별로.
- 세대 이름 헌금은 세대주 앞으로 합산, 맞벌이 부부는 비율(예 6:4)로 나눔. **나눠도 합계가 1원도 안 바뀌게** 원 단위 끝수 처리 규칙을 정한다.
- 받을 사람이 소천·이명이면 발급 전 경고.
- 검증: 발급 합계 + 보류 합계 = 그 해 헌금 총액.
- 주민등록번호는 **저장하지 않고** 빈칸으로 인쇄(손으로 기입).
- 서식은 국세청 기부금영수증 서식에 맞춘다(서식 번호·항목은 구현 전 최신 고시로 확인). 교회 고유번호가 없으면 발급 화면에서 안내.

### 3단계 — 돌봄과 연동 (선택)
- 이번 달 생일·오래 못 만난 분, 심방 기록.
- 주보(M7)에 이번 주 생일자 넣기 단추.
- 재정 잠금(아래 5장).

### 하지 않는 것
출석부, 문자 발송, 예산·결재·마감, 부서·구역 조직, 지출 영수증 사진, 휴대폰 앱, 서버 동기화. — 요청이 쌓이면 다시 본다.

## 5. 개인정보·보안

- 헌금·교적은 **종교에 관한 정보 = 민감정보**(개인정보 보호법 제23조). 처리자는 교회이고, 세라핌은 교회 PC 안에서만 돌아가므로 제3자 보관·위탁이 생기지 않는다.
- **재정 잠금:** 「교회 행정」을 열 때 PIN. 재정 담당과 목회자를 나누고 싶은 교회를 위해 「교적만 보기」 PIN을 따로 둘 수 있게(목회자가 개인별 헌금액을 보지 않도록).
- **DB 암호화:** 1단계는 OS 사용자 계정 보호 + PIN. 파일째 가져가도 못 읽게 하려면 SQLCipher 계열이 필요한데 의존성·빌드가 무거워진다 → 1단계에서는 하지 않고 「정할 것」에 둔다.
- 백업 zip에 행정 자료가 들어가므로 **백업 파일 암호** 옵션이 필요(2단계까지).
- 교인 동의서 양식(민감정보 별도 동의)을 안내서에 넣는 것을 검토 — **법률 검토 전 단정하지 않는다.**

## 6. 데이터 설계(초안, 금액은 모두 원 단위 정수)

| 표 | 주요 열 |
|---|---|
| `households` | id, name, head_member_id |
| `members` | id, household_id, name, role(직분), phone, birth(음력 여부), status, note |
| `offering_types` | id, name, sort |
| `offerings` | id, date, member_id 또는 household_id(둘 중 하나), type_id, amount, memo |
| `expense_types` / `expenses` | id, date, type_id, amount, memo |
| `receipt_splits` | year, household_id, member_id, ratio |
| `visits`(3단계) | id, member_id, date, kind, memo |

기존 `src/main/db/schema.ts`의 마이그레이션 방식과 `dao.ts` 패턴을 그대로 따른다.

## 7. 화면(세라핌 안)

- 상단에 「교회 행정」 버튼 → 별도 창이 아니라 **전체 화면 모달**(송출 화면과 섞이지 않게).
- 탭: 주간 입력 · 장부/요약 · 교인 · 영수증 · 가져오기/내보내기.
- 주간 입력 화면이 첫 화면. 매주 하는 일은 이것 하나.

## 8. 순서와 대략 작업량

| 단계 | 내용 | 대략 |
|---|---|---|
| 0 | 맥 최신 코드(0.2.0~0.3.1 실제 소스)를 GitHub에 올림 — **이게 먼저** | 운영자 5분 |
| 1 | 장부·교인·월 요약·붙여넣기 가져오기·CSV 내보내기 + 계산 점검 | 큼 |
| 2 | 기부금영수증 + 백업 암호 | 중간 |
| 3 | 생일·심방·주보 연동·재정 잠금 PIN | 중간 |

각 단계는 시범 교회 1곳(예: 효범님 교회)의 실제 엑셀 한 해치를 넣어 **합계가 원본과 1원까지 맞는지**로 끝을 판단한다.
