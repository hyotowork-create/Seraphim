# KSA-FLOW — 자금집행·내부통제 시스템 설계기획서

> **용도**: 이 문서를 Claude Code 프로젝트 루트에 `SPEC.md`로 두고, 아래 "구현 순서"대로 마일스톤 단위 지시.
> **원본 참고**: 통합 자금집행·내부통제 아키텍처(홈택스→ERP→승인→은행). 본 문서는 이를 **소규모 사단법인(직원 2~5명) 규모로 축소·현실화**한 버전.

## 0. 설계 원칙 (축소 판단 근거)

| 원본(대기업 ERP) | KSA-FLOW (현실화) | 이유 |
|---|---|---|
| 홈택스 API 실시간 연동 | 홈택스 **엑셀 다운로드 → 업로드 파싱** | 공식 API는 세무대리인용, 상용API(팝빌)는 유료 — Phase 2 어댑터로 유보 |
| 펌뱅킹 자동 수집 | 은행 **거래내역 엑셀 업로드 → 자동 대사** | 펌뱅킹 계약 불필요, 월 1~2회 업로드로 충분 |
| 자동 이체 실행 | **대량이체 파일 생성** → 인터넷뱅킹 수동 업로드 | 출금이체 API는 기관계약 필요, 소규모엔 과잉 |
| 그룹웨어 위임전결 엔진 | **금액 기준 2단계 결재** (전결 규정 설정값) | 결재선 3인 이내 |
| 별도 모바일 앱 | **반응형 웹 + 이메일 승인 링크** | 앱 배포 비용 제거 |

유지하는 핵심 사상: **① 증빙이 먼저, 지출은 증빙에서 파생 ② 모든 단계에 잔액·권한 Gate ③ Maker ≠ Checker ≠ 최종승인 ④ 감사로그 append-only**

## 1. 기술 스택

- **Next.js 14+ (App Router) + TypeScript** — 단일 리포지토리 풀스택
- **DB**: SQLite + Prisma (5인 이하 조직에 충분, 파일 백업 용이. 추후 PostgreSQL 전환 가능하도록 Prisma 스키마에 SQLite 전용 기능 사용 금지)
- **인증**: NextAuth — 이메일+비밀번호(credentials). 세션 기반, 역할은 DB
- **UI**: Tailwind CSS + shadcn/ui, 모바일 우선 반응형
- **파일 저장**: 로컬 `./storage/evidences/` (PDF·이미지·엑셀 원본 보관, SHA-256 해시 기록)
- **엑셀 파싱**: `xlsx`(SheetJS) — 홈택스·은행 내역 파싱, 이체파일 생성
- **배포**: 단일 VPS(Docker) 또는 사내 미니PC. Vercel 사용 시 DB는 Turso로 교체

## 2. 역할·권한 (책임분리 원칙)

| 역할 코드 | 대상 | 권한 | 금지 |
|---|---|---|---|
| `STAFF` | 담당자 | 증빙 등록, 지출결의 작성(Maker), 본인 건 조회 | 승인, 지급 확정 |
| `ADMIN` | 사무국장 | 1차 승인, 예산·거래처·월계획 관리, 지급배치 생성 | **본인이 작성한 결의 승인 불가**, 최종승인(한도 초과 건) |
| `DIRECTOR` | 상임이사 | 최종승인(E1), 전체 조회 | 결의 작성, 지급파일 생성 |
| `AUDITOR` | 감사 | 전체 읽기 전용 + 감사로그 열람 | 모든 쓰기 |
| `SYSADMIN` | 시스템관리자 | 사용자·설정 관리 | **결의 작성·승인·지급 전부 불가** |

하드 룰(코드 레벨 강제):
1. `request.createdBy === approver.id` 이면 승인 API 403
2. 지급배치 생성자(Checker)는 해당 배치 내 결의의 작성자가 아니어야 함
3. `SYSADMIN`은 업무 트랜잭션 엔드포인트 전체 403

## 4. 상태머신 & 통제 Gate

```
DRAFT ──제출──▶ [G1·G2·G3 검사] ──▶ SUBMITTED
SUBMITTED ──사무국장 승인 [G4]──▶ 금액 < 전결한도 ? ADMIN_APPROVED(종결) : 상신
상신 ──상임이사 승인 [G4]──▶ FINAL_APPROVED
승인완료 ──배치 편성 [G5]──▶ PAYMENT_READY ──이체파일 생성·실행──▶ PAID
PAID ──은행내역 매칭──▶ RECONCILED
어느 단계든 REJECT ──▶ REJECTED (사유 필수) ──수정──▶ 재제출(새 Approval 이력)
```

| Gate | 검사 내용 | 실패 시 |
|---|---|---|
| **G1 예산잔액** | `annualLimit - Σ(승인·지급된 동일코드 금액) ≥ amount` | 제출 차단 |
| **G2 월계획** | 해당 월 계획 잔액 확인 | 경고만 (Phase 1) |
| **G3 증빙필수** | 증빙 ≥ 1개, 세금계산서면 totalAmt===amount, ntsNumber 중복 없음, 재사용 차단 | 제출 차단 |
| **G4 권한분리** | 작성자 ≠ 승인자, 역할·단계 일치 | 403 |
| **G5 지급검증** | 승인완료만 편성, 계좌 verified, 중복 편성 차단, 배치생성자 ≠ 작성자 | 편성 차단 |
| **G6 감사로그** | 모든 상태변경·승인·설정변경을 트랜잭션 내 AuditLog 기록 | 실패 시 롤백 |

## 8. 구현 순서 (마일스톤)

**M1. 기반** *(인증·역할·감사로그)* — ✅ 완료

**M3. 지출결의·승인** — 미착수
**M4. 지급·대사·대시보드** — 미착수
